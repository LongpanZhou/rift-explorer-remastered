## Problem Statement

The phone page works, but it does not look or behave like the client. It is a plain list of names with separate Hover and Lock buttons, and it sits on its own Phone tab even though it belongs to Auto champ select. Two asks: move the phone entry point under Auto champ select as a button, and make the phone champ select mirror the in-client screen, including summoner spells.

## What Makes This Cool

Open the phone during champ select and see what the client shows: portraits, the bans row, the timer, your spells, the champion grid, Lock In. Tap a portrait to hover it, tap Lock In to commit. Nothing to explain to a teammate.

## Constraints

- Same Wi-Fi only. The server still runs on the Mac, with no internet relay.
- The phone page stays plain HTML and script with no outside files. Icons come through the Mac (decision 3).
- Riot's UI art and fonts are not added to the repo. Icons are the Data Dragon images the desktop app already uses.
- No League client was running during this planning, so every field marked **verify** must be checked in a live champ select before release.
- Nothing is pushed. Local main has unpushed commits, including 853b28c (phone page).

## Premises

These are my assumptions. Tell me if any is wrong.

1. "Exactly like in game" means the same screen zones, the same portraits and spell icons, and the same flow (tap to hover, Lock In to commit). Pixel-identical is out of reach without Riot's UI art.
2. The phone is held in landscape, as the client is. Portrait works too, with the same zones stacked.
3. The client hides enemy summoner spells during champ select, so the mirror shows them hidden. **verify**
4. Runes are the "etc". They come second, after spells and swaps.

## Approaches Considered

### Approach A: Restyle the current page
Keep the list layout. Add portraits, spell icons, a bans row and the timer. Keep the Hover and Lock buttons.
- Effort: S (human ~3 days / CC ~1 hour). Risk: Low.
- Pros: smallest change, reuses every current route.
- Cons: keeps the flow you asked to change. The grid is still a plain list.

### Approach B: Mirror the client layout (recommended)
Landscape first. Bans across the top. Your team on the left with portrait, spells and position. Champion grid in the middle with search. Enemy team on the right. Bottom bar with your spells, rune page, timer and Lock In. The phone state carries champion ids, aliases, spells and the timer, and the Mac proxies the icons.
- Effort: M (human ~1.5 weeks / CC ~2-3 hours). Risk: Medium, because several LCU fields are unverified.
- Pros: matches the layout and the flow you asked for.
- Cons: more fields to check live. The rune page switch is unverified.

### Approach C: Pixel replica from client art
Pull the client's frames, backgrounds and fonts from a League install or CommunityDragon.
- Effort: L. Risk: High.
- Pros: closest look.
- Cons: adds a licensing question and a large asset set for a small visual gain. Rejected for now, can revisit.

## Recommended Approach

Approach B. It is the only option that gives the in-client read you asked for. A keeps the flow you want changed. C adds licensing work for a small gain.

Decisions inside B (made without asking, change any of them):

1. **Entry point.** A card directly under the Auto champ select hero with one button, "Phone champ select". Press it to start the phone server and show the QR code and passcode in the card. Press again to stop. The Phone tab is removed. The server still stops when you leave the Auto section, as it does now.
2. **Layout.** Three columns in landscape: your team | champion grid | enemy team. The bans row sits on top and the bottom bar holds spells, rune page, timer and Lock In. Portrait stacks the same zones. The page still polls every 2 seconds and counts the timer down locally in between.
3. **Icons.** The Mac serves champion and spell icons from Data Dragon at `/icon/champion/{alias}.png` and `/icon/spell/{file}`, cached in memory for a day. The phone needs no internet for images. An `<img>` cannot send the passcode header, so icon routes accept the passcode as `?k=`, the same way the page link carries it. The Data Dragon version comes from `versions.json`, the same source the desktop app uses.
4. **Spells.** The spell list comes from Data Dragon `summoner.json` (names, keys, icon files), replacing the hardcoded list in the page. Spells disallowed for your position come from `/lol-gameflow/v1/session/per-position-summoner-spells/disallowed` and are greyed out. Setting one slot sends both slots, with the other slot's current value. **verify** the response shape.
5. **Hover and lock.** Tapping a portrait hovers it at once. Lock In commits it. This matches the client. The current Hover button goes away.
6. **Enemy spells.** Shown as hidden slots. The page does not guess them.
7. **Positions.** Text labels (TOP, JGL, MID, BOT, SUP). Data Dragon has no position icons.
8. **Champion filter.** Search always. Role chips from the `roles` field in `champion-summary.json` if that field is there. **verify**
9. **Runes (phase 2).** The bottom bar shows the current rune page name. Tapping it lists your editable pages, and picking one sends `PUT /lol-perks/v1/pages/{id}` with `current: true`. The existing rune save already uses that path. The switch behavior is **unverified**.
10. **Swaps (phase 2).** The text box moves to a swap button on each teammate's cell, as in the client. It keeps its "not tested in a live game" label until checked live.
11. **Page file.** Move the page out of the TypeScript template string into its own HTML file. Check that the compiled sidecar still embeds it.

### Layout

```
+----------------------------------------------------------------+
| PICK 0:24          [ bans, your team ]  [ bans, their team ]    |
+------------------+---------------------------+-----------------+
| YOUR TEAM        | [ search ]  [ role chips ]| ENEMY TEAM      |
| [img] TOP  You   |  champion grid            | [?] hidden      |
|   [D][F] Garen   |  tap = hover              | [img] Ahri      |
| [img] JGL  Lee   |  greyed = taken           | [img] Jinx      |
|   [D][F]         |                           |                 |
+------------------+---------------------------+-----------------+
| [D][F] spells    |        [ Lock In ]        | [Rune page: 1]  |
+----------------------------------------------------------------+
```

## Verify in a live champ select

These fields were not checked, because no client was running:

- `session.myTeam[].spell1Id` and `spell2Id` for teammates, and whether `theirTeam` hides enemy spells
- `session.myTeam[].assignedPosition`
- `session.timer.adjustedTimeLeftInPhase` (units and freshness)
- the response shape of `per-position-summoner-spells/disallowed`
- the `roles` field in `champion-summary.json`
- the rune page switch body (`current: true`)
- swap request and accept semantics

A custom game with bots gives a champ select with teammate cells, so these can be checked without a ranked queue.

## Open Questions

- Does the phone page need to work outside Auto mode? Assumed yes. It runs independently of the Auto switch.
- Windows: the phone page is still unavailable there. Not in this design.

## Success Criteria

- In a champ select, the phone shows portraits, the bans row, the timer and your spells within 2 seconds of the client showing them.
- Tapping a portrait hovers it in the client. Lock In locks it. A champion a teammate has is greyed out.
- Changing spells on the phone changes them in the client.
- The phone gets icons with the Wi-Fi having no internet access.
- The page works at 390x844 (portrait) and 844x390 (landscape) with no horizontal scroll.
- Existing phone tests pass. New tests cover icon passcode checks, the disallowed-spell check, and the hover-on-tap call.
